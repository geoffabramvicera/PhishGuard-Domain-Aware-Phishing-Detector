      System overview

      How the system works

      The project has a training stage and a prediction stage. Training creates the model file; the running backend uses that saved model to analyze URLs submitted from this page.

      01

      Load labeled examples

      phishing_dataset.csv contains URL examples labeled legitimate or phishing. The labels provide the answers used during training.

      02

      Extract URL features

      url_features.py turns each URL into numeric values covering URL length, host structure, path and query patterns, suspicious terms, and hostname entropy.

      03

      Train the classifier

      train_model.py trains a hybrid classifier using domain character n-grams and numeric URL features. It evaluates on held out registrable domains and saves phishing_model.pkl.

      04

      Submit a URL

      This page sends the submitted text to the local Flask API at 127.0.0.1:5000/predict. The submitted website is not opened.

      05

      Generate a prediction

      The backend extracts numeric features, encodes hostname character n-grams, and combines both signals. A narrow homepage rule recognizes selected exact HTTPS homepages but never automatically trusts arbitrary subpages.

      06

      Review the result

      The page shows the prediction, estimated phishing score, and feature values. The feature list describes the model inputs, not the exact cause of its decision.

      Getting started

      How to use the application

      On your computer, the backend and frontend run in two separate PowerShell windows. You only need to train the model again if the model file is missing or the data or feature logic changes.

      Start the application on Windows

      Run these commands from the folder containing app.py and index.html.

      1. Train the model, first run onlyPowerShell
      .\.venv\Scripts\python.exe train_model.py
      2. Start the Python backendTerminal 1
      .\.venv\Scripts\python.exe app.py

      Leave this window open. It runs the API on port 5000.

      3. Start the website serverTerminal 2
      py -3.12 -m http.server 8000

      Run from the project folder, then open http://localhost:8000/index.html.

      If you have not installed packages yet, run .\.venv\Scripts\python.exe -m pip install -r requirements.txt first. Stop either server with Ctrl+C.

      Model inputs

      URL features used by the model

      The classifier receives both numeric hostname and URL structure features and character n-grams from the hostname. Character n-grams let it learn patterns inside the domain name without treating every unseen domain as automatically safe or dangerous. The signals help classification but do not explain every individual prediction.

      Use responsibly

      What this prototype can and cannot do

      Understanding the limits is part of interpreting a machine learning security result correctly.

      What it does

      • Extracts structural and hostname aware features from the URL text.
      • Uses a locally saved hybrid classifier that combines hostname character n-grams with structured domain and URL features.
      • Displays the prediction, the raw phishing score, and the URL feature values.
      • Runs without a paid external prediction service.

      What it does not do

      • Does not open, crawl, or scan the submitted website.
      • Does not check live domain reputation, domain age, DNS, redirects, or page content. Hostname spelling analysis is not the same as verifying a domain against a current threat intelligence database.
      • A known-domain signal can reduce an obvious false alarm, but it cannot prove that an individual path, repository, download, or user-generated page is safe.
      • Does not guarantee that any URL is safe or malicious.
      • Does not provide a calibrated real world probability of phishing.
      PhishGuard

      Educational machine learning prototype. Use the output as one signal only, not as a substitute for browser protections or independent security checks.
